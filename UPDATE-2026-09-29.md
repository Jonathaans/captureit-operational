## Yang berubah

- **Notifikasi:** ikon lonceng membuka panel pengingat berdasarkan hak akses dan penugasan. Tersedia filter belum dibaca, tandai semua dibaca, muat ulang, dan tautan ke tab event terkait. Status baca tersimpan per akun di database. Panel diperbarui setiap satu menit selama halaman aktif.
- **Mapping Kendaraan:** menu untuk menambah/mengedit kendaraan internal atau sewa, nomor polisi, vendor, serta status aktif. Event coordinator mengetik kendaraan dan driver melalui **Atur mapping** atau tab **Logistik & Export** di detail event. Driver dapat diisi dari nama tim atau diketik untuk driver eksternal.
- **Jadwal kendaraan:** isi tanggal/jam loading dan perkiraan kendaraan kembali dalam WIB. Aplikasi menolak pemakaian kendaraan yang tumpang tindih, termasuk loading sehari sebelum event atau perjalanan setelah event. Jika perkiraan kembali kosong, batas pemakaian adalah waktu selesai event. Kendaraan bisa dipakai event berikutnya tepat pada batas akhir tersebut. Event yang dibatalkan tidak memblokir kendaraan. Perubahan jadwal dari Calendar yang menimbulkan benturan ditandai di notifikasi dan detail event.
- **Export Excel:** sheet **Events**, dengan 21 kolom dalam urutan file acuan, header biru, baris header tetap terlihat, filter, tanggal Excel, dan angka ribbon. CSV memakai kolom yang sama. Export tetap hanya mencakup event yang dikoordinasikan akun tersebut, sesuai rentang tanggal mulai event dalam WIB.
- **Logout:** tombol **Keluar workspace** dengan ikon pintu dan dialog konfirmasi berisi identitas akun. **Tetap di sini** membatalkan. **Ya, keluar** menghapus sesi server, menghentikan kamera bila aktif, dan membersihkan data halaman sebelum kembali ke login. Kegagalan logout ditampilkan di dialog agar bisa dicoba lagi.

## Mengisi data untuk export

1. Pilih event dan klik **Atur mapping**, atau buka detail event → **Logistik & Export**. Ketik nama kendaraan langsung, lalu isi driver. Daftar kendaraan dapat dipakai bila ingin melengkapi nomor polisi, jenis internal/sewa, atau vendor. Vendor wajib bila kendaraan diatur sebagai sewa.
2. Isi tanggal dan jam loading. Kedua isian loading harus dilengkapi bersamaan dan tidak boleh melewati waktu mulai event.
3. Isi Client Name, Client Phone, Service Type, Equipment Setup, dan Sales. Service Type merupakan jenis layanan seperti **Classic**, terpisah dari kategori event Calendar seperti Wedding/Corporate. Isian yang belum tersedia akan kosong di export.
4. Isi Ribbon Awal dan Ribbon Akhir sebagai **sisa kapasitas cetak**, bukan angka meter yang bertambah. Total Penggunaan = awal − akhir dan dihitung otomatis. Nilai nol dipertahankan; total kosong bila salah satu angka belum diisi. Untuk pemakaian beberapa roll, gunakan rincian di tab **Penutupan**; setelah laporan diterima, export memakai jumlah semua roll dari laporan tersebut.
5. Klik **Simpan logistik & detail**. Buka **Jadwal Event**, pilih rentang tanggal, lalu **Export Excel**.

Kolom export: Event Name, Client Name, Client Phone, Service Type, Equipment Setup, Sales, Petugas, Event Date, Start Time, End Time, Loading Date, Loading Time, Location, Status, Vehicle Name, Driver Name, Vendor Sewa, Ribbon Awal, Ribbon Akhir, Total Penggunaan, Notes.

Petugas ditulis `Nama (PIC), Nama (CREW)`. Status menggunakan `SCHEDULED`, `CANCELLED`, `PENDING_EVALUATION` (event sudah clear tetapi masih ada petugas belum dinilai), atau `COMPLETED`. Kode CRM tetap tersimpan pada aplikasi; kolom kode tidak ditambahkan ke format acuan ini. Nomor telepon tetap berupa teks, tanggal tanpa pecahan waktu, jam dalam WIB, serta total ribbon berupa formula dengan nilai tersimpan. Teks yang menyerupai formula tidak dijalankan sebagai formula dari input pengguna.

## Akses dan notifikasi

Pengelolaan armada memakai hak `events.assign` yang sudah ada. Mapping dan isian export boleh diubah coordinator pemilik event; event tanpa coordinator akan menjadi milik akun yang pertama menyimpan mapping. Head Operations dan Administrator dapat mengelola semua event. Akun lain yang dapat melihat event hanya dapat membaca detailnya. Hak khusus role yang telah dikustomisasi tetap mengikuti konfigurasi aplikasi.

Notifikasi mencakup penugasan Crew/PIC, kekurangan tim/transportasi, kesiapan alat, progres desain, persetujuan/transfer uang jalan, evaluasi tertunda, pembatalan, dan benturan kendaraan. Pengingat tim, transportasi, alat, dan desain muncul untuk event tujuh hari ke depan. Panel menampilkan event pada jendela 30 hari ke belakang/ke depan dan menghilangkan pengingat yang sudah terselesaikan. Notifikasi ini berada di dalam aplikasi; tidak mengirim pesan WhatsApp, email, atau push saat aplikasi ditutup. Tidak ada pengiriman pesan otomatis ke pihak lain.

## Memperbarui instalasi

Gunakan folder instalasi yang sekarang agar konfigurasi dan volume database tetap sama.

1. Cadangkan database beserta folder upload melalui prosedur backup yang biasa dipakai. Hentikan layanan sebelum mengganti kode atau membuat salinan langsung file database.
2. Salin file aplikasi dari paket ini ke folder instalasi yang sama, termasuk `operations.py`, `static/operations-ui.js`, `static/operations.css`, serta **folder `templates`**. Pertahankan `.env`, database, volume Docker, dan folder upload yang sudah ada. Tidak perlu menjalankan `reset_operational_data.py`.
3. Untuk Docker, jalankan dari folder Compose lama:

   ```bash
   docker compose stop captureit-ops
   docker compose up -d --build captureit-ops
   ```

   Gunakan nama project Compose yang sama dengan instalasi sebelumnya. Jangan memakai `docker compose down -v`, karena perintah itu menghapus volume data.

4. Untuk instalasi Python, hentikan proses lama dan jalankan kembali `python3 server.py` dari folder aplikasi setelah menyalin file. Python 3.10+; tidak ada paket runtime tambahan.
5. Buka ulang halaman atau lakukan hard refresh. Penambahan tabel dilakukan otomatis saat startup. Tidak ada reset akun, event, fee, payroll, atau ACL.

Kendaraan nonaktif tidak dapat digunakan untuk penugasan baru; mapping yang sudah ada tetap tersimpan. Perubahan nama/vendor pada master kendaraan juga tampil di export event yang memakai kendaraan tersebut. Data logistik tidak ditimpa oleh sinkronisasi Calendar. Utilitas reset operasional, bila sengaja dijalankan, membersihkan mapping melalui penghapusan event dan status baca notifikasi, tetapi mempertahankan master kendaraan.
